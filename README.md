## Лабораторная работа №10 — Добавление рассылки в очередь задач

1. Миграция `2026_11_19_000005_create_jobs_table.php` создаёт `jobs` и `failed_jobs`.
2. `QUEUE_CONNECTION=database` установлен в локальном `.env.example`.
3. Создано задание `app/Jobs/VeryLongJob.php`.
4. В `NewsController::store()` вместо немедленной отправки вызывается `VeryLongJob::dispatch($article->id)`. Сама отправка через `ArticleCreatedMail` выполняется в методе `handle()`.
5. Работник запускается `php artisan queue:work database --tries=3 --sleep=1`.
6. После создания новости задача появляется в `jobs`, а после обработки письмо фиксируется в `storage/logs/laravel.log`, если используется `MAIL_MAILER=log`. Для настоящего email нужен SMTP.

### Локальная установка для преподавателя (без хостинга)

Требуется PHP **8.3+** (pdo_sqlite, mbstring, openssl, fileinfo), Composer или готовая папка `vendor`.

```bash
composer install
php scripts/setup-local.php
```

**Первый терминал:**

```bash
php artisan serve --host=127.0.0.1 --port=8000
```

**Второй терминал:**

```bash
php artisan queue:work database --tries=3 --sleep=1
```

Откройте http://127.0.0.1:8000. Учётные данные локального модератора автоматически записываются в `LOCAL_LOGIN.txt` (не публикуется в Git). Можно запустить всё сразу через `START_MAC.command` или `START_WINDOWS.bat`.

Для демонстрации постановки задачи в очередь **сначала остановите worker**, создайте статью, убедитесь, что в `jobs` есть задание, потом запустите `queue:work`.

```bash
php artisan queue:failed
php artisan test
```

Секреты хранятся только в локальном `.env`; `database.sqlite`, `LOCAL_LOGIN.txt`, `vendor` и логи исключены из Git. Повторная установка **не удаляет** новости.

## Хостинговая версия

Ветка `hosting-laravel13` использует MySQL InfinityFree и отдельный `.env.example` без паролей. Перед загрузкой нужны подготовленные Composer-зависимости, настройки базы и почты. Из-за ограничений бесплатного хостинга указывать `QUEUE_CONNECTION=database` **нельзя, если worker не запущен**, иначе письма навсегда останутся в очереди. Для сайта используем `sync`; для демонстрации именно фоновой очереди предназначена `main`.

## Лабораторная работа №11 — широковещание (Pusher + Laravel Echo + Vue)

При публикации статьи сервер создаёт событие \`App\Events\NewArticleEvent\`, реализующее \`ShouldBroadcast\`. Оно вещает в **публичный** \`Channel('articles')\` под именем \`NewArticleEvent\`. \`broadcastWith()\` передаёт \`article.id\`, \`article.title\` и внутреннюю ссылку \`article.url\`. Черновики не отправляются; если черновик впервые опубликован, событие тоже передаётся. Отправка почты через \`VeryLongJob\` из №10 остаётся без изменений.

Фронтенд: \`resources/js/components/App.vue\` показывает розовое всплывающее уведомление; \`resources/js/bootstrap.js\` создаёт клиент Pusher/Laravel Echo, слушатель подписан на \`articles\` и \`.NewArticleEvent\`. Сборка — через \`vite.config.js\`, \`package.json\`, \`npm run build\`. Разметка Vue подключена в \`resources/views/layouts/app.blade.php\`.

### Как включить настоящие push-уведомления

1. Создайте приложение **Pusher Channels**, выберите кластер **eu**. Сохраните его **App ID, Key, Secret**. Без аккаунта Pusher готовая реализация не сможет доставить сообщение в браузер.
2. Скопируйте \`.env.example\` в собственный \`.env\`, укажите \`PUSHER_APP_ID\`, \`PUSHER_APP_KEY\`, \`PUSHER_APP_SECRET\`, \`PUSHER_APP_CLUSTER=eu\` и **\`BROADCAST_CONNECTION=pusher\`**. Для совместимости с заданием можно также указать \`BROADCAST_DRIVER=pusher\`. Секрет никогда не публикуется в Git или браузере.
3. Выполните \`php artisan config:clear\`. Для локальной разработки установите PHP/JS-пакеты: \`composer install\`, \`npm install\`. Для стабильной демонстрации соберите production JS через \`npm run build\`. Команда \`npm run watch\` доступна для разработки через Vite, но требует включённого dev-сервера.
4. **Локально:** оставьте \`QUEUE_CONNECTION=database\`, запустите \`php artisan serve\` и **отдельно** \`php artisan queue:work database --tries=3 --sleep=1\`. При изменении .env перезапустите worker. **InfinityFree:** оставьте \`QUEUE_CONNECTION=sync\`; никакого фонового процесса на сервере запускать не нужно.
5. Откройте сайт в одном окне браузера как посетитель, а во втором войдите модератором и опубликуйте новость. В первом окне должно появиться всплывающее уведомление со ссылкой. После отправки не следует закрывать вкладку посетителя.

**Где брать готовые сборки:** [GitHub Actions](https://github.com/alinakashafutdinova/Servernaya_web-razrabotka_10-15/actions) собирает отдельно ZIP для \`main\` (SQLite + \`vendor\` + \`public/build\`) и для \`hosting-laravel13\` (MySQL + \`vendor\` + \`public/build\`). Обычный GitHub Download ZIP не включает \`vendor\` и готовый JS; для него нужны Composer и npm.

**Технические ограничения:** InfinityFree не предоставляет WebSocket-сервер, но браузеры могут подключаться к **внешнему** Pusher. В хостинговой ветке отправка события происходит в режиме \`sync\`. Без ключей Pusher оставляйте \`BROADCAST_CONNECTION=log\` — остальной сайт будет работать, но онлайн-пушей не будет.

В Laravel 13 публичный канал не требует добавления устаревшего \`App\Providers\BroadcastServiceProvider\` в \`config/app.php\`. Основная конфигурация вещания находится в \`config/broadcasting.php\`, фронтенд собирает Vite. Автотесты проверяют контракт события, публичный канал, полезную нагрузку, публикацию черновика и сохранение очереди №10. Проверка фактической внешней доставки через Pusher требует действующих ключей.
